# Gap Analysis

Status: **Pending current-state and target-state analysis**

Do not populate gaps solely from assumptions. Each gap must compare evidence of current behaviour against an approved requirement, architectural constraint, quality standard, or acceptance criterion.

## Gap format

| ID | Area | Current state | Target state | Gap | Severity | Affected repos | Proposed action | Status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

## Categories

- functional completeness
- user workflow / UX
- architecture
- API/contracts
- data integrity
- authentication/authorization
- privacy/security
- reliability/error handling
- performance/scalability
- observability
- maintainability/technical debt
- UI/E2E automation
- API automation
- unit/component/integration testing
- CI/CD and quality gates
- documentation/operability

## Prioritization

Prioritize using product impact, user impact, defect/security risk, dependency criticality, implementation effort, and ability to unblock other work.
